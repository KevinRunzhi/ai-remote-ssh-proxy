# v0.3 开发候选使用说明

此包尚未完成正式验收，请仅用于明确选择的可信测试容器。Remote SSH 首次准备、用户商店安装 Codex、真实代理请求归因及全新 B 验收仍待验证。程序不下载或自动安装插件。

当前内部 Codex 适配候选为 26.1021.22027，尚非支持结论。检查以 VS Code 的有效注册包为依据，忽略卸载残留；注册或调用链异常时保留现有安装并报告，不自动升级或降级。

1. 完整解压到普通本机目录，双击 `start.cmd`。无需独立安装 Node/npm，不需要管理员权限或策略放宽。
2. 使用 Windows 系统 OpenSSH/curl、VS Code Stable 的默认用户配置和 Remote SSH。软件缺失时按照页面官方入口准备。自定义 profile、Server 路径尚不支持。
3. 粘贴简单 SSH 命令，填写本机无认证 HTTP 代理，确认新建/重建声明。每次写入先核对预览。密码只在原生终端 OpenSSH 提示中输入，工具不保存密码。
4. 按页面提示连接、重连；自行在目标远端窗口的 VS Code 商店安装指定版本 Codex，并在官方界面登录。程序检查实际结果，准备未完成可稍后继续。
5. 检查、收到新回复、实际代理路径分别显示。没有路径归因证据不能报告完全验收通过。
6. 正常移除代理保留 SSH 连接；旧容器不可达可单独弃用，明确选择是否清理本机增量。新目标永远使用新身份。
7. 关闭页面不会停止任务。退出请使用“退出工具”，等待原生终端收尾。未知写入保留恢复记录，不能手工删除状态文件。

用户状态保存在 `%LOCALAPPDATA%/codex-remote-ssh-proxy-e2e`，不在工具包目录。更新/换解压目录不会迁移或覆盖它。`build-manifest.json` 列出逐文件摘要、Node 官方来源和依赖版本；旁边 `.sha256` 核对 ZIP。摘要用于检测损坏，不构成签名。

遗留锁先在原生终端受控核对：系统互斥只允许一个恢复入口，确认旧实例/恢复进程已结束、没有 SSH/SCP 且记录未变化后，输入 `RECOVER` 才接管工具锁；不重放配置或迁移。当前实现保守地检查系统全部 SSH/SCP，因此其他 SSH 会话也可能阻止接管；请正常关闭相关连接再试，工具不会代为结束。PID 复用、证据不足或损坏记录均停止并保留原件。后续网页中的旧记录迁移/入口核对仍需单独预览确认。

维护者 CLI：在原生终端使用随包 `runtime/node.exe scripts/e2e.mjs configure|verify|remove|abandon`。CLI 与网页共享状态和锁；已有实例时使用原窗口。历史 `--remote-settings` 仅用于与实际 Server 路径核对，不授权任意路径写入。

旧记录的远端结果 unknown 且缺少可关闭的写入许可时，不能仅凭旧 phase 自动继续或移除；可通过“弃用旧容器”保留远端并归档后新建目标。核对发现本机文件冲突时，页面允许明确全部保留，不覆盖用户修改。此限制不代表旧远端已清理。
