## 1. 背景、事实与产品假设

v0.1 已记录完成 Windows → Linux → VS Code Remote SSH 中 Codex 的真实代理链路验证，并交付 configure、verify、remove 三个 CLI 命令。记录包含配置、重连、目标进程代理环境、用户新请求与进程连接关联、重复配置和安全撤销。55 项自动测试通过是既有记录，不是 v0.2 的新验证结果。

当前已知使用步骤仍包括：安装 Node.js 与依赖、确认 SSH alias 与配置入口、输入本地代理、查找远端 settings 绝对路径、执行命令、完全重连、再次检查与人工请求确认。CLI 已经支持缺失参数时交互询问，不能把“增加问答”本身当作新版主要收益。

产品假设：将入口放到用户正在使用的 VS Code 中，减少环境准备和路径查找，并明确重连后的检查动作，可以降低独立上手难度。当前没有独立用户试用数据，需通过本版可用性验收验证该假设。

## 2. 目标用户与版本目标

### 2.1 目标用户

- 使用 Windows 桌面版 VS Code，已有可正常连接的 Remote SSH 目标。
- 远端是受信任的 Linux，目标 Codex 扩展已安装并登录、实际运行在远端。
- Windows 已安装可用的 OpenSSH 和 curl，本地已有正在运行的无认证回环 HTTP 代理。
- 用户可以输入 SSH 密码、确认配置变更、重连窗口和发送 Codex 请求，但不要求理解反向转发原理或手工编辑配置。

### 2.2 核心目标

用户安装扩展后，通过 VS Code 命令面板完成目标选择、代理配置、重连引导、独立检查与移除。常规且已验证的环境不需要用户查找远端 settings 绝对路径，也不需要拼接脚本命令。

安装验收目标是：最终用户无需单独安装 Node.js、运行 npm ci、获取源码或进入项目目录。实现方式必须先验证；开发者的构建环境不受这一目标限制。

受支持的 VS Code 版本范围是安装前提，随 VSIX 说明给出；低于最低版本应在安装或启动时明确拒绝。默认 Windows PowerShell 执行策略下的启动体验须实际验证，不把修改用户策略作为未披露前提。

### 2.3 成功的含义

- 使用门槛降低：未参与开发的目标用户可依据交付说明独立完成全过程。
- 证据保持准确：配置已写入、网络检查通过、用户确认可用、代理路径归因分别表达。
- 配置保护不退步：保留原配置、幂等、安全撤销和失败恢复仍是交付条件。

## 4. 用户入口与交互约定

命令名称为产品文案草案，命令标识在技术方案中确定：

| 命令 | 职责 |
| --- | --- |
| 远程 Codex 代理：配置 | 选择目标、收集输入、只读检查、预览、确认、写入与重连指引 |
| 远程 Codex 代理：检查 | 展示当前管理目标与已有记录，执行本次独立检查，引导真实请求确认 |
| 远程 Codex 代理：移除 | 预览并安全撤销工具拥有的修改，提示再次重连 |

- 不要求用户打开特定项目目录才能运行命令。
- 本地窗口可启动配置；Remote SSH 窗口中的操作仍须访问 Windows 本地资源。具体运行机制通过阶段 P0 证明。
- 检查和移除优先使用活动恢复记录；当前窗口与记录目标不一致或无法关联时明确展示目标，不能静默改用当前窗口。
- 任一步输入取消都正常结束；正式变更确认前不写目标配置、不创建活动恢复记录、不上传真实配置内容。
- 确认后处理中显示进度和当前目标。关闭提示框或取消进度不等于配置已恢复；按实际写入阶段报告结果。
- 不创建专用侧边栏、Webview 页面或常驻仪表盘。

## 5. 配置流程

### 5.1 前提检查与目标选择

1. 检查 Windows 本地执行环境与必要的系统工具。
2. 确认将使用的 SSH 配置入口，展示其路径。支持默认入口与用户指定文件；必须与用户实际 Remote SSH 连接使用的入口一致。
3. 只列出首版规则支持的唯一、单 alias 字面 Host；保留手工输入受支持 alias 的入口。
4. SSH 配置包含 Include、Match 等首版拒绝的布局时，明确说明不支持，不通过筛选列表掩盖冲突。
5. 有活动目标时显示其 alias 与代理映射。同一目标按现有幂等规则处理；另一目标停止并提示先移除，不能覆盖记录。

目标列表来自已有配置，不自动发现服务器，不创建 SSH 账号或连接配置。无法从当前 VS Code 窗口可靠获得 alias 时仍由用户选择，不依赖未验证的内部接口猜测。

### 5.2 代理输入

- 用户提供回环 HTTP 代理地址和端口；可给格式示例，不把示例端口当作已发现的值。
- 远端端口默认 17890，允许修改；沿用端口和 URL 校验。
- 检查本地代理可用性，拒绝认证代理、SOCKS URL、非回环地址及其他首版不支持的输入。
- 来源不明的远端端口占用仍停止；不自动切端口、停止进程或接管转发。
- 复用活动记录中的非敏感输入；不新增历史参数库。

### 5.3 远端设置路径辅助定位

目标是让受支持的常规安装不需要用户查路径，同时保持“实际路径有依据”的约束：

- 只通过固定、有限的只读检查获得候选与依据，不全盘扫描远端文件。
- 只有路径能够关联到目标用户及实际使用的 VS Code 服务端安装时，才可作为可靠推荐；仅发现标准路径或某个文件存在不够。
- 展示候选路径和简短来源说明，并纳入最终变更预览。
- 多候选或证据不足时，提供“在目标窗口打开 Remote Settings (JSON)，确认实际路径”的具体指引与手工输入入口。
- 文件尚不存在时仍须确认所在安装与目录依据，再沿用安全创建规则；不任意创建猜测目录。
- 本版先验证一套标准安装路径。自定义服务端目录、多安装共存等环境可走手动确认，不承诺自动识别。

确切识别方法与支持条件由技术验证确定，并在发布说明列明。如果标准样本也无法可靠识别，则该需求未通过，不能用自动选中惯用路径替代验收。

### 5.4 预览、确认和写入

- 展示目标 alias、SSH 配置路径、本地与远端端口、远端 settings 路径以及两处精确增量。
- 明确远端 Machine 代理设置可能影响同一远端用户下其他遵循该设置的扩展。
- 用户明确确认后，复核摘要、保存恢复信息、执行局部修改并复读验证。
- 重复配置无增量时说明复用结果；用户已有等价值不取得所有权。
- 写入完成提示“配置已写入，需要重连”，不能显示“Codex 已可用”。

### 5.5 重连引导

提示用户保存工作、完全关闭连接该目标的远端窗口、使用同一 alias 重连、重新打开 Codex，然后运行“检查”。说明仅关闭 Codex 面板可能仍复用旧后端。

用户点击“我已重连”只能开始新检查，不能直接改变检查结论。插件不自动关闭窗口、Kill Server、结束 Codex 进程或操作 Remote SSH 私有命令。

## 6. 检查流程与状态表达

### 6.1 配置记录与本次观察分开显示

| 信息 | 展示要求 |
| --- | --- |
| 无活动记录 | 提示先配置；不据此宣称机器上没有用户自行配置的代理 |
| 已有配置记录 | 展示目标和映射；不等于当前隧道已生效 |
| 正在检查 | 展示当前层级，支持安全取消 |
| 本次检查通过 | 展示检查时间与各层结果；继续提示人工请求确认 |
| 证据不足 | 说明缺少的证据及下一步，不显示通过 |
| 检查失败 | 展示阻塞层、简短原因与可执行下一步 |
| 需要恢复 | 展示记录位置、已知残留与安全恢复指引 |

远端没有监听可能需要重连，也可能是转发失败；不能一律断言用户未重连。插件重启或窗口重载后，历史检查结果只能标为历史，本次实时状态须重新检查。不承诺后台监控。

### 6.2 五层自动检查

沿用本地代理、SSH、远端回环入口、目标 HTTPS、实际 Codex 后端代理环境五层检查。验证连接不得创建被验证的转发；目标 HTTPS 必须验证 TLS，正确区分服务响应与代理错误。

多个 Codex 后端候选时，引导用户确认目标进程；不能选择第一个候选。进程信息在远端过滤，只返回判断所必需的内容，不传回完整环境或凭证。

具体引导先展示候选的启动时间、版本与已核实的归属线索。普通用户可保存工作、手动关闭同一目标其他 Codex 会话，保留目标窗口再检查；工具不自动结束进程，也不要求用户凭 PID 猜测。若仍无法唯一关联则明确显示证据不足并提供重试，不能宣称完整验收成功。高级 PID 输入保留身份校验；P2 必须验证这条多候选处理流程，A08 不改为部分通过。

### 6.3 用户真实请求与代理路径证据

- 自动主动网络探测结束后，再引导用户在目标 Codex 窗口自行发送新请求。
- 提供用户主动启动的有限时长只读连接观察流程，建议初始观察窗口为 60 秒；具体交互在技术设计中验证。
- 必须先明确目标 app-server 进程，再观察其与远端代理端口的连接关联；多个候选无法区分时停止归因。
- 用户确认收到新回复与进程连接证据分别记录。只有二者在本次观察流程中成立，才能显示“本次实际使用及代理路径已确认”。
- 用户收到回复但观察未命中时，显示“用户确认可用，代理路径未证实”；不能直接认定请求失败。
- 观察结束或取消后不遗留后台观察进程；仅保留脱敏结果，不采集请求内容或认证头。

## 7. 移除、恢复与生命周期

- 移除先预览工具拥有的修改，明确确认后按摘要安全恢复；保留用户等价配置及后续修改。
- 移除完成仍提示用户重连，不能把配置删除等同于当前 SSH 连接监听已消失。
- 插件窗口关闭、重载或操作中断后，下一次操作先核对活动记录与实际状态。不能因进度界面消失就删除记录或声称回滚。
- 沿用 CLI 的活动记录与操作锁语义，保证 CLI 与插件并发时不能同时写入。记录结构若需变化，先设计显式兼容或迁移，禁止静默丢弃旧恢复信息。
- v0.1 已有活动配置必须能够被插件识别、检查和安全移除；不要求用户手工删除 active.json。
- 卸载扩展不会自动撤销远端配置；使用说明明确要求需要撤销时先运行“移除”。恢复记录不能只放在随扩展版本替换的安装目录中。
- 状态未知时保留记录，列明目标配置与本次残留位置；不得自动覆盖或清理未知文件。

## 8. 认证与安全要求

插件界面不收集、保存、代填 SSH 密码。认证继续交给系统 OpenSSH 原生终端交互；不使用 AskPass、密码参数或密码环境变量，不关闭主机密钥检查。不同 SSH/SCP 连接允许分别提示认证，不承诺一次输入。

认证负担需要量化：按 configure、verify、remove 分别记录独立连接数、实际密码输入次数、失败重试/恢复额外次数及用户中途放弃情况。当前静态基线中首次配置常见成功路径为 10 条连接、完整 verify 为 6 条，均不含失败恢复，且不等于固定密码次数。优先评估同阶段只读检查合并，不引入连接复用、不削弱确认和恢复边界；本轮不承诺未经实测的次数上限。

配置预览和检查输出只展示必要信息；不在输出面板打印原始配置、完整进程环境、密码、Token 或密钥。沿用参数数组、固定远端模板、摘要核对、局部编辑、受限暂存和安全恢复要求。

实际密码交互载体、操作结果获取与子进程生命周期必须在 P0 验证。若实现需要插件截获密码输入，或需要用户额外安装 Node.js 才能正常完成流程，则不符合当前方案，须记录阻塞并重新评审。

## 9. 技术方向与待验证问题

以下是实现约束与候选方向，不是已完成架构：

- 扩展在 Windows 本地运行，处理本地代理与 SSH 配置，通过已有 SSH 路径访问 Linux。VS Code 官方提供本地 UI 扩展运行机制，但本项目尚未验证。
- 优先复用现有配置编辑、传输检查、恢复与工作流逻辑；将必要的终端交互依赖适配到扩展入口，不重写整套核心。
- 扩展与 CLI 共用行为规则；不为将来产品建立通用适配器、插件框架或稳定外部协议。
- 扩展运行环境内直接复用逻辑、认证所需本地终端以及可能的辅助进程如何组合，由 P0 证据决定。
- 不能假设 Remote SSH 窗口中新建的任意终端都位于 Windows 本地，也不能假设扩展宿主具有交互终端。
- 最低 VS Code 版本、运行时兼容范围和确切 API 使用在 P0 后确定，交付前必须明确记录，不使用未经验证的最低版本声明。

## 10. 阶段、交付物与停止条件

| 阶段 | 工作与交付 | 完成条件 |
| --- | --- | --- |
| P0：插件可行性验证 | 最小试验扩展、脱敏版本与结果记录；只执行固定只读操作 | Windows 本地执行、SSH 原生密码与取消、结果获取、无需独立 Node.js、重连后再次检查全部有真实证据 |

| P2：检查与移除闭环 | 分层结果、真实请求观察引导、兼容旧记录、安全移除与恢复说明 | 自动检查、用户新回复、进程连接关联、重复配置、撤销及必要失败分支均有证据 |
| P3：VSIX 与独立试用 | 可安装包、简短中文说明、支持版本、脱敏验收记录 | 未参与开发的用户在受支持环境独立完成安装到请求成功及移除 |

P0 的验证环境不具备或用户尚未完成必要认证、重连时，如实标记未验证。不得以本地模拟替代真实密码与远端窗口运行证据。

P0 未通过时，不推进完整插件实现，不自动改做 EXE、不降低密码支持要求、不把额外安装 Node.js 变成隐含前提。先记录具体原因，再评审是否修改范围或实现路径。

P0 按依赖推进：终端本地性 → 默认执行策略下的投递 → 最小原生认证、连续密码提示及流式结果 → 其余清理、运行时和重连验收。前两步不建设完整通信框架。若远端窗口无法可靠启动本地认证终端，默认判 A02 未通过并停止；仅在本地窗口运行须另行确认并修改本 PRD，不作为自动降级。默认策略启动失败同样不自动要求用户放宽策略。

P0 只读完成后，更新专门的 v0.2 技术设计与实施计划；现有 v0.1 架构和 Spec 保留历史定位。后续实现顺序以冻结 PRD 和已验证技术路径为依据。

| A11 | 写入失败、响应丢失、重载与并发 | 已知修改尝试恢复，未知状态保留证据；CLI 与扩展互斥写入 | 受控故障测试 |

| A13 | 输出与暂存 | 测试秘密不进入输出、记录或公开验收材料；暂存清理失败明确报告 | 自动测试 |

真实环境不进行破坏性故障注入；失败与中断分支优先使用受控夹具验证。验证深度按改动风险确定，保留现有相关测试并增加有实际行为价值的插件边界测试。

独立试用记录应包含完成与失败的步骤、需要帮助的位置、手工输入路径次数、各命令密码输入次数（重试/恢复单列）、因重复认证放弃的情况和粗略耗时。首轮不设缺乏依据的分钟数指标；若仍需开发者指导，则 A14 未通过，记录原因并修正文案或流程后再验收。

## 12. 本版不做

- 多目标同时管理、历史事务列表、跨 alias 共享配置协调。
- Include、Match、通配 Host 等复杂 SSH 配置兼容性扩展。
- 自动发现或管理代理软件、自动切换端口、后台保活、定时监控。
- 自动登录 Codex、读取登录凭证、自动重连 VS Code 或自动发送模型请求。
- 独立 Windows EXE、复杂安装器、扩展市场发布、自动更新、多平台支持。
- Webview、自定义侧边栏、远端常驻服务、通用 SSH 管理或适配器体系。

## 13. 评审与冻结要求

本稿把已确认方向细化为建议范围，尚未把所有技术问题视为已解决。评审应确认：三命令入口、单目标约束、路径识别回退、引导式进程观察、旧记录兼容、免装 Node.js 与独立用户试用是否均纳入本版。

冻结后，任何目标变化先更新本 PRD；P0 中的实现选择只要满足需求与安全边界，可依据证据确定。若必须放弃某项验收才能继续，则需要显式修订范围，不能在实施计划中悄悄降低要求。
