# Separate the tunnel core from tool adapters

The product will model SSH proxy forwarding independently from developer tools, while Codex and Claude Code are handled by first-party Tool Adapters. This preserves a simple initial experience for the two named tools without binding tunnel diagnosis, planning, or rollback to either vendor, allowing more tools to be supported later without redesigning the core workflow.

## Consequences

The product targets first-party Codex and Claude Code adapters, but delivery is staged: v0.1 ships tunnel-only operation and Codex, while Claude Code follows in v0.2. The internal Tool Adapter seam remains provisional while Codex is its only implementation and is considered validated only after the independent Claude Code adapter uses it without bypasses. A public third-party adapter interface is deferred until that internal seam has proved stable. Tunnel-only operation remains valid when no tool is selected or installed. Adapters detect Supported Tool Capabilities instead of inferring compatibility only from version strings. A selected but unavailable tool is Configured-Unverified rather than reported as healthy, while an installed tool with unknown capabilities is diagnosed without mutating its configuration.

Tool Adapters inspect tool-specific state, return Desired State Contributions, and provide tool-specific Verification evidence. They do not write files, execute arbitrary remote scripts, create Configuration Transactions, or decide Rollback. A shared Remote Environment module owns the product environment file, supported Bash/Zsh loading blocks, NO_PROXY merging, and the optional VS Code Server environment. The Claude Code adapter may additionally contribute its tool-specific user setting. Applying the Remote Environment to every terminal or the VS Code Server remains a separate, explicit choice.

Interactive Bash/Zsh startup and the VS Code Server are distinct Environment Carriers that are selected and verified independently. An unsupported or unknown shell fails that shell scope without mutation; it does not invalidate tunnel-only operation. Codex is reported configured only when at least one Environment Carrier applicable to its actual launch path is selected and verified, rather than inferring success from an unrelated shell or server environment.

The interactive Bash/Zsh carrier uses only a fixed loading block and an allowlisted generated environment file. Values are serialized with strict POSIX single-quote encoding and reject NUL, newlines, and control characters. The block must remain non-fatal under `set -e` and `set -u`; the complete prospective startup file and generated environment file pass the selected shell's syntax-only check before mutation, and an isolated interactive shell verifies the resulting variables afterward. Fish, tcsh, and unknown shells are unsupported in v0.1 rather than receiving guessed syntax.

A central Plan Compiler turns contributions into a deterministic linear Operation Plan. Each typed operation carries its resource identity, preconditions, postconditions, compensation data, and sensitivity classification, while explicit barriers separate mutation from Verification. The Transaction Executor applies operations in order and compensates the successfully applied stack in reverse order. Raw shell commands, adapter-owned ordering, and adapter-owned apply or rollback callbacks are not accepted contribution types; a general dependency DAG is deferred until a real concurrency requirement justifies it.

For v0.1 Codex scopes, the Remote Environment standardizes the required upper- and lower-case HTTP proxy values after explicit approval of any non-secret user-owned conflict, preserves existing NO_PROXY entries, and appends missing loopback entries; Rollback restores every original string. If an affected prior value contains embedded credentials or is otherwise classified as secret, v0.1 fails closed and asks the user to migrate or remove it manually rather than persisting secret compensation data. In v0.2, the Claude Code adapter contributes a syntax-aware minimal JSON/JSONC property patch that preserves comments, formatting, line endings, and unknown fields. Invalid syntax, duplicate target keys, or ambiguous structure fails closed instead of falling back to full-file serialization.

Each Tool Adapter also owns a versioned Probe Policy for no-model-call evidence. The tunnel core executes constrained probes and reports their observations, while the adapter distinguishes network reachability, authentication state, and insufficient evidence; vendor URLs and interpretations never become tunnel-core or public protocol constants.

Existing user-owned proxy values are reused when equivalent and treated as conflicts when different. Replacing them requires explicit approval and remains reversible. NO_PROXY entries are merged without duplication, while Rollback restores the exact prior value.
