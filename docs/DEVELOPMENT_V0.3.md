# v0.3 开发候选使用说明

当前为未验收开发候选。五操作、CLI 和本地页面已共用工作流。2026-10-24 最新生产候选 e8598f09 已通过真实五层检查、正常移除保留 SSH，以及建立新周期后恢复配置；Codex 重连后界面正常，并已收到本次真实新回复。远端 settings 是等价复用，没有取得移除所有权。首次安装和干净 A→B 集中验收尚未完成；[交接记录](HANDOFF_V0.3_2026-10-24.md)保留历史暂停快照。任务和证据边界以 [验证记录](E2E_RUN_V0.3.md) 最新补记及 [候选说明](CANDIDATE_V0.3.md)为准。插件由用户在 VS Code 商店安装；工具只引导和检查，不下载插件或安装 VSIX。

维护者在仓库根目录运行 `node scripts/prepare-runtime.mjs`，从固定官方来源准备运行时、校验摘要并取得许可证；随后双击根目录 `start.cmd`。开发准备需要现有 Node 和系统 curl，最终交付用户不需要这些开发步骤。下载失败不得改用来源不明二进制或关闭 TLS。

启动后保留原生终端，浏览器填写本次选定的测试目标，可粘贴受支持的简单 `ssh -p 端口 用户@主机` 命令。直接基础预检使用 `-F none`；实际创建 alias 前确认 VS Code Remote SSH 使用同一 config。当前入口可在明确预览确认后修改工具拥有的连接/代理增量。

密码和主机身份确认只在 OpenSSH 原生终端处理。不要把密码填入网页或命令；不要分享启动 URL。主机密钥异常时停止并按可信平台指纹核实，不关闭校验或自动删除 known_hosts。

页面刷新只读取状态；关闭标签页不会取消。使用“取消操作”或“退出工具”等待实际收尾。再次双击发现已有实例时使用原窗口；未知遗留锁不自动抢占。受控恢复入口已实现并通过原生 RECOVER 实测，仅在进程普查及来源核对通过、用户明确确认后接管，不重放配置；完整强关等生命周期验证仍待完成。

维护者验证：`npm test`；受控浏览器夹具与真实 SSH 结果分别登记，不将夹具成功标成真实认证通过。

维护者打包：`node scripts/package.mjs`，然后 `node scripts/check-package.mjs`。运行时及内部产物保持 Git 忽略；夹具 `scripts/browser-fixture.mjs` 和 `scripts/trial-ssh.mjs` 不在生产白名单。

2026-10-24 上午已按用户要求恢复开发。维护者有限只读连接采集见[采集说明](PROXY_OBSERVATION_V0.3.md)：正常退出网页后独占运行，自动探测结束后才观察目标进程 socket，不发送模型请求。它不在生产白名单，不把受控测试结果计作真实请求归因。
