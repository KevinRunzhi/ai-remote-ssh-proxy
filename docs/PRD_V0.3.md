## 1. 要解决的问题

用户频繁在云平台新建 Linux 容器，并通过 Windows 上的 VS Code Remote SSH 开发。每次都需要处理连接信息、本地代理转发、远端 VS Code 设置、Codex 扩展准备、登录、重连和验证。配置分布在本机与容器中，步骤难记，旧容器销毁后还可能被旧恢复记录阻塞。

本版目标：用户安装一次本地工具，以后提供新容器的 SSH 连接信息，即可在同一个引导流程中完成环境准备、代理配置与使用检查，无需查找配置文件、手工编辑 JSON 或拼接脚本命令。

“一键”指统一入口和自动配置；SSH 密码、主机身份确认、Codex 登录、必要的 VS Code 点击和重连仍由用户完成，不承诺零交互。

## 2. 现状与新增范围

### 2.1 已有事实

- v0.1 已交付 `configure`、`verify`、`remove`，历史记录包含真实请求成功、代理路径归因、重复配置和安全撤销。
- 现有自动测试基线为 55 项通过；这是既有 CLI 的证据，不代表本版新增流程已验证。
- 当前 CLI 要求用户事先具备可用 SSH alias、远端 Codex 安装与登录，并提供实际 Remote settings 绝对路径。
- 核心代理修改是 Windows SSH config 中的反向转发，以及 Linux VS Code Machine settings 中的两个代理字段。
- 当前一次只允许一个活动恢复记录；更换目标要求先移除旧目标，不适合旧容器已经销毁的情况。
- v0.2 插件只有规划文档，没有已验证的插件实现。

## 3. 使用范围与前提

### 3.1 支持环境

- Windows 11 本机、桌面版 VS Code、系统 OpenSSH 和 curl。
- 云平台提供可用 SSH 服务的受信任 Linux 容器；用户有地址、端口、用户名及可用认证方式。
- 本机已有正在运行的无认证回环 HTTP 代理。两端端口允许不同，远端入口限定 `127.0.0.1`。
- 先支持一套实测的标准 VS Code Server 安装布局；实施前选定候选 Windows/VS Code/Remote SSH/Linux/Codex 组合与 Linux 架构、基础库、工具和 SCP/SFTP 能力，实测后将精确版本及限制写入交付说明。历史样本不是新流程已通过的证据。

容器创建与付费、服务器 SSH 服务和转发权限、代理软件运行由用户及云平台提供。工具检查这些前提并说明阻塞原因，不自动改服务器认证或权限策略。

### 3.2 首次本机准备

不要求用户已经配置过目标容器。缺少 VS Code、Remote SSH、OpenSSH 或 curl 时，工具应明确指出缺失项，给出具体安装指引并允许完成后继续；本版不制作系统软件安装器，也不静默执行系统提权安装。

常规新容器流程中，VS Code Server、远端 Codex 扩展和代理设置均须纳入准备与检查，不能继续作为用户已经完成的隐藏前提。

## 4. 用户流程

### 4.1 首次运行

1. 解压工具包，双击启动并打开本机浏览器页面；不要求特定工作目录或管理员权限。
2. 检查本机必要工具，确认实际 VS Code 和 SSH 配置入口；自定义位置可手工选择。
3. 输入本地 HTTP 代理地址和默认远端代理端口，检查格式与可用性。
4. 用户确认后保存非秘密偏好，后续初始化预填；允许随时修改，不自动发现代理软件。

### 4.2 初始化新容器

1. 输入地址、SSH 端口、用户名，或粘贴受支持的简单 SSH 连接命令；也可选择已有受支持 alias。
   初始化入口必须明确选择“新建/重建容器”；“继续原容器”使用已有目标记录，不按相同 alias 或地址自动选择继续。
2. 显示解析结果，确认本次目标及本地参数。SSH 密码不进入表单或连接字符串。
3. 检查 SSH 认证、文件和端口条件；需要认证时交给 OpenSSH 原生提示。
4. 预览并确认本机 SSH 连接信息和反向转发增量，保存恢复信息后局部应用。
5. 打开或引导连接对应 VS Code 远端窗口，完成标准 VS Code Server 准备。
6. 识别实际远端 Machine settings 路径，预览并确认代理字段增量，再安全写入；该步骤不要求预装 Codex。
7. 引导保存工作并重连，使代理配置生效；检查远端 Codex 扩展，缺失时由用户在目标远端窗口的 VS Code 商店安装，工具等待并重新核对结果。
8. 需要时再次提示完全关闭对应远端窗口，用同一 alias 重连并打开 Codex；未登录时引导用户完成官方登录。
9. 执行独立检查，提示用户发送真实请求并确认新回复。

这是用户流程顺序，不预定具体安装命令。首次连接、扩展下载和代理生效存在依赖，必须用全新容器验证可行顺序；不得以“扩展先装好”跳过引导，也不得在未知安装目录中提前写入猜测路径。

### 4.3 再次启动

- 显示目标、已完成步骤和下一步；记录代表上次进度，不代表当前远端在线或代理可用。
- 提供“继续原容器初始化”“检查”“移除代理配置”“弃用旧容器并初始化新容器”的明确选择。
- 继续前核对真实状态，复用已完成工作；不重复创建 alias、转发片段或代理字段。
- 标准环境无需手填 Linux settings 路径或输入项目命令。非标准环境可提供明确的路径确认指引；无法确认则停止。

### 4.4 本地网页

- 单页提供连接与代理输入、目标摘要、步骤进度、变更预览，以及初始化、继续、检查、移除和弃用操作。
- 页面展示明确的下一步和安全错误说明；刷新后可重新取得当前进度，不会重复启动或重放写入。
- SSH 密码与主机身份提示留在原生终端；Codex 登录使用官方流程。页面不提供密码或 Token 输入框，不复制原始终端会话。
- 页面关闭不代表取消或恢复完成；提供取消和退出工具入口，并展示实际处理结果。
- 页面及操作入口只允许本机访问，启动临时本地进程；不部署网站，不接入云端账户或常驻后台服务。
- 同一用户数据目录只允许一个工作实例；再次双击仅提示使用原窗口，不启动第二条初始化或恢复流程。

## 5. 配置与安装职责

| 位置或事项 | 工具负责 | 用户负责 |
| --- | --- | --- |
| 本机代理偏好 | 保存、预填、校验地址与端口 | 首次提供实际地址，启动代理 |
| Windows SSH config | 新建独立目标块，或预览后局部修改受支持目标；添加转发 | 提供连接信息，确认增量和主机身份 |
| VS Code 本机准备 | 检测并给出安装或定位指引 | 完成必要的软件安装 |
| VS Code Server | 通过 Remote SSH 标准流程触发准备并核对结果 | 必要的连接确认与密码输入 |
| 远端 Codex 扩展 | 给出商店安装引导，核对远端安装、版本与运行位置 | 在目标远端窗口的 VS Code 商店安装并登录 |
| 远端 Machine settings | 定位实际文件，局部设置 `http.useLocalProxyConfiguration=false` 和 `http.proxy` | 确认变更；非标准路径按指引确认 |
| 重连与真实请求 | 保存进度、给出准确步骤、检查结果 | 保存工作、重连、发送请求并确认回复 |

远端设置可能影响该用户下其他遵循代理设置的扩展，预览必须说明。不扩展为所有终端或整个容器的全局代理；不复制整份旧容器配置，不修改 `.bashrc`、系统环境或 Codex 登录文件。

安装行为与配置事务分开报告：移除代理配置不会卸载 VS Code Server 或 Codex 扩展，安装失败也不等于所有配置都已撤销。

“移除代理配置”只撤销工具拥有的反向转发和远端代理字段，保留已完成并确认的 SSH 连接信息与 alias；不依赖被移除的代理继续联网。弃用时可另行预览清理工具新建的连接块，用户原有连接不因弃用而删除。新建连接和代理增量必须保留各自的归属与恢复依据。

## 6. 必须具备的行为

### 6.1 输入、偏好与连接

- 常规输入至少覆盖主机名或 IPv4 地址、用户名、SSH 端口，沿用密码或用户已有密钥认证；不管理私钥内容。
- 粘贴的连接命令只解析支持的字段，禁止直接执行整段输入；不支持的选项给出原因及分字段输入入口。
- 保存偏好与每个容器的恢复信息分开，放在不会被工具包替换或解压覆盖的本机用户数据目录。
- 修改偏好只影响后续预填，不重写当前目标参数；有未移除代理增量的目标不支持原地换端口或换代理，先按原记录移除，再确认新的配置。既有等价值仍受冲突保护。
- 已有 alias 与连接信息冲突时，展示冲突并允许使用新的独立 alias，不静默重定向已有目标。
- 沿用普通文件、唯一单 alias 字面 Host 块的支持范围；Include、Match、重复目标和链接文件等不支持布局明确停止，不为本版扩展通用 SSH 配置解析。

### 6.2 幂等、取消和恢复

- 目标配置写入前预览精确增量并确认；前期检查不写目标配置。保存偏好和安装动作单独说明用途并取得对应确认。
- 保留无关配置、注释和用户等价值，复用等价值不取得删除所有权。
- 写入前后核对摘要，保留最小恢复信息；当前配置步骤失败时尝试恢复该步骤的已知改动，保留此前成功阶段。安装、登录或网络检查失败标为未完成，提供重试或移除，不盲目回滚整次初始化。
- 同一容器重复运行不增加配置，保留首次恢复依据；用户后续修改时停止覆盖或自动撤销。
- 关闭窗口、认证取消、超时和中断后，下一次启动核对记录与真实状态再继续，不直接显示成功。
- 保留工具与旧 CLI 的互斥写入保护，兼容 v0.1 活动记录；不要求用户手工删除 `active.json`。
- 记录各资源是否尚未触及、已经复用、写入中、已应用、已恢复或结果未知；“尚未触及远端 settings”不能被当作缺少记录的错误。仅本机代理已写入时，移除该增量不要求远端在线，也不要求先取得 settings 路径。
- 取消先停止推进并核对原操作，再使用独立、有界的收尾流程；不得让已取消信号终止恢复。不能证明原远端写入已经结束时，冻结对该资源的后续写入，显示需要恢复，不能边写边回滚。
- 状态文件切换中断时，无歧义的元数据可核对后完成；有歧义则冻结受影响操作并在页面解释可选动作，不让用户手改 JSON。任何自动核对都不等于自动重放目标配置写入。

阶段行为至少满足下表；阶段完成不等于当前网络仍然可用：

| 当前状态 | 继续或失败处理 | 移除与远端依赖 |
| --- | --- | --- |
| 只读预检，尚无配置修改 | 可重新检查；取消无需配置恢复 | 无代理增量可移除 |
| SSH 连接已完成，代理尚未应用 | 保留连接，继续转发配置 | 正常移除保留连接，无需远端 |
| 本机转发已完成，远端 settings 从未触及 | Server/安装失败保留进度；可重试 | 可仅撤销工具转发，无需远端 |
| 远端 settings 写入中或结果未知 | 先确认原写入已结束，再核对修改前后摘要；不盲目重写 | 未确认前不宣称已移除；保留恢复依据 |
| 两处代理配置已确认，后续安装/登录/检查失败 | 保留配置，重新检查后继续 | 远端字段恢复需认证；再撤销本机转发，保留连接 |
| 已移除代理 | 记录移除结果；重新配置须重新预览确认 | 保留连接及必要记录；不自动回放旧代理计划 |

### 6.3 更换与弃用容器

本版支持顺序初始化和替换容器，并为各次目标保留必要恢复记录；不做批量部署或多容器运维面板。

- 旧目标在线且需要撤销时，可按既有规则安全移除工具拥有的修改。
- 旧容器已经销毁时，用户明确确认“弃用”后归档旧记录，新目标初始化不得依赖旧目标能重新连接。
- “弃用”不等于远端清理成功；应保留远端未清理或无法确认的状态，列明本机配置的保留或清理计划。
- 本机清理仅处理可核实归属的旧目标增量，并单独预览确认；不得整文件回滚覆盖其他目标或用户新增内容。摘要冲突时保留旧内容，允许用无冲突的新 alias 初始化新目标。
- 同一 alias、地址或端口可能被云平台分配给新容器，不能仅凭这些字段套用旧配置摘要或逆操作。用户选择新建/重建时必须建立新记录，禁止对该目标使用旧远端逆操作；继续原容器须明确声明并辅助核对用户、路径及可得主机密钥依据，不一致时停止。不承诺自动识别用户误声明且所有线索相同的克隆或重建。
- 主机密钥变化继续由 OpenSSH 检查；不自动删除 known_hosts 条目或关闭检查。未确认身份前不能绕过检查继续连接。
- 密钥确因重建变化时，给出向云平台等可信渠道核实新指纹、由用户按 OpenSSH/VS Code 官方流程处理对应旧条目、再返回重试的指引。工具不修改 known_hosts，也不用新 alias、HostKeyAlias 或禁用检查绕过冲突。该安全异常可需要用户额外命令或文件操作，单独记录，不算标准样本的零手工配置路径。
- 归档记录中标注的旧目标若重新出现，不自动恢复管理或重放旧操作。
- 弃用允许保留旧远端的未知状态；归档前必须确认本机原操作已退出且本机配置稳定。旧目标未知的远端写入不会被自动重试，也不会通过新容器的路径去核对或恢复。

### 6.4 结果表达

至少区分：等待本机准备、等待认证、等待安装或首次连接、配置已写入待重连、自动检查通过、用户确认可用、证据不足、失败、需要恢复、旧目标已弃用但远端未确认清理。

自动检查沿用本地代理、SSH、远端回环入口、目标 HTTPS、实际 Codex 后端代理环境五层语义。检查连接不能创建其正在验证的转发，HTTPS 探测须校验 TLS。

真实请求由用户发起。收到回复与确认代理路径分别表达；交付验收保留目标 Codex 进程到代理端口的关联证据，不以同时段代理日志代替。该归因可由维护者使用有限只读验收工具完成，本版不要求制作完整观察界面。没有关联证据时不得显示“代理路径已确认”。

### 6.5 首次安装与版本

- 按 2026-10-24 用户确认，插件由用户在目标远端窗口的 VS Code 商店安装；工具只提供引导、等待继续及安装后的版本/平台/位置检查，不实现插件下载、自动安装或官方 VSIX 回退，不暂存安装包。
- 分别证明 Remote SSH 的 Server 准备、用户商店安装的远端 Codex 及 Codex 实际请求；工具 curl 经代理成功不等于商店安装成功。商店不可用时保留配置进度并说明阻塞，用户处理商店访问后继续。
- 交付前固定已验证组合；新安装优先使用已验证版本的公开安装路径。已有或后来更新的版本重新核对，不兼容时保留进度并停止；不静默降级或禁用自动更新。取得或安装已验证版本的公开路径不可行时，先内部验证替代组合并更新交付基线，不能无提示改装最新版。

## 7. 安全边界

- 继承 SECURITY.md：信任本机用户及远端 Linux；不支持不受信任的共享服务器。
- SSH 密码和主机认证由 OpenSSH 处理；工具不读取、保存、代填密码，不要求改成密钥登录，不承诺只输入一次密码。
- 不读取、迁移、打包或修改 Codex 登录凭证，不自动登录，不自动发送模型请求。
- 不记录完整配置、完整进程环境、Token、私钥或请求内容；本机偏好和目标元数据不自动上传。
- 不关闭 TLS 校验，不将代理监听暴露到公网，不修改服务器 sshd 配置或停止占用端口的未知进程。
- 受系统策略阻止启动时明确报告，不静默放宽 PowerShell 执行策略或其他系统策略。
- 本版允许经确认新增连接配置、保存偏好和目标记录、调用公开入口准备 VS Code。自动强制关闭窗口、Kill Server、结束用户 Codex 进程仍不在范围内。

## 8. 交付与开发方式

### 8.1 交付物

1. 一份 Windows 解压即用工具包，包含双击入口、轻量本地网页、所需运行环境及依赖；不要求独立安装 Node.js 或使用源码。
2. 简短中文使用说明，覆盖本机首次准备、初始化、继续、检查、移除和弃用旧容器。
3. 实测支持版本与环境、已知限制、脱敏验收记录和失败恢复指引。

暂不强制合并成单个 EXE，不制作安装向导、自动更新、插件下载器或 VS Code 插件 VSIX。工具包仍包含固定校验的 Node 运行时，保证无需独立安装 Node 即可启动。内部 CLI 保留用于开发和排障，正常用户流程不依赖手动执行 CLI。

### 8.2 推进原则

- 先在内部验证打包启动与原生密码交互、全新容器的安装网络及路径识别、旧容器不可达时的替换，再接齐整体流程；这些是内部检查，不拆成需要用户逐版确认的产品版本。
- 复用 v0.1 核心，新增入口、偏好、目标生命周期和必要的环境准备适配；不先重写传输或配置系统。
- 不将 v0.2 的 PowerShell/插件通信方案、P0–P3 流程或独立用户试用门槛搬成本版前置条件。
- 自动验证由开发侧完成；真实密码输入、登录、重连和请求由用户在集中验收时段完成。失败需修复复验，不以“一次验收”限制必要检查。
- 安装依赖和版本行为若无法满足本 PRD，报告具体阻塞，显式修订范围；不临时改成插件项目或隐藏增加用户手工命令。

## 10. 本版不做

- VS Code 专用插件、复杂图形界面、Webview、常驻仪表盘。
- 调用云平台 API 创建、续费、销毁容器，制作自定义容器镜像。
- macOS/Linux 本机、VS Code Dev Containers、WSL、跳板及复杂 SSH 布局适配。
- 多容器批量部署、并行操作、通用 SSH 管理、历史事务浏览系统。
- 代理自动发现、代理软件管理、全局终端代理、后台隧道保活和定时监控。
- 凭证迁移、免密登录配置、服务器认证修改、自动登录和自动模型请求。
- 覆盖与联网无关的全部 VS Code 个性化设置或容器开发依赖。
