# v0.3 维护者只读连接采集

这是 Spec §6.3 允许的有限只读验收工具，用于补充 A08 的目标进程到代理端口证据。它不属于五种业务操作，不写业务记录或用户配置，不随生产 ZIP 交付，也不改变网页的“代理路径未归因”显示。2026-10-24 已取得真实 Linux 目标进程的新代理连接，并在同一观察窗口由助手代操作官方界面取得新回复；这是当前容器的局部实测，不替代干净 A→B 或用户本人确认。详见[验证记录](E2E_RUN_V0.3.md)。

## 使用前提与运行顺序

1. 在产品中完成本次可信容器初始化、安装、重连和五层检查。确认目标是记录中的原容器；从该目标的检查证据取得已核对的 Codex app-server PID，多候选不能任选。
2. 在页面点击“退出工具”，等待正常退出。采集入口也要取得实例锁；已有网页、CLI 或其他采集者运行时拒绝，不抢锁。遗留锁先走产品受控恢复，采集工具不会删锁。
3. 在仓库根目录的 Windows 原生交互终端运行：

   ```powershell
   node scripts/observe-proxy.mjs --target-id <当前目标UUID> --pid <已确认PID> --seconds 60
   ```

   维护者可使用已有开发 Node，或将 `node` 换成本仓库固定的 `runtime/node.exe`。此命令不是最终用户安装步骤。
4. 阅读目标、alias、PID 与时长，输入 `ORIGINAL` 声明原容器。必要密码只进入 OpenSSH 原生提示；采集脚本不读取 stdin 密码、不处理官方登录。
5. 工具先独立运行五层检查。全部结束后，才启动一次新的只读 SSH 观察；看到终端“只读采集已开始”时，在目标官方 Codex 界面发送一次请求。观察期间不要运行其他验收网络探针。
6. 观察结束后，只有在刚才窗口内实际发起请求并收到新回复，才输入 `REPLY`；否则直接回车。进程连接与用户新回复分别记录。

结果保存在本机忽略目录 `.cache/proxy-observation-<随机UUID>.json`，只保存目标/周期/revision、时间、PID/启动标识、代理端口、匹配 socket inode 与受限结果。没有主机地址、凭证、请求正文、完整进程环境或其他网络连接地址。不要将实际证据直接发布到公开仓库。

## 证据规则与限制

- 输入只接受 UUID、正整数 PID、支持平台及 1–120 秒的有限窗口；通过现有隔离 SSH 调用，不建立转发或使用连接复用。
- 必须是当前 active 目标及 configured 周期，资源已应用/复用且没有未完成写入。旧记录、待核对切换、配置未完成、不同目标或有效 SSH 入口改变时停止；采集不迁移或恢复。
- 远端核对当前 UID、候选版本/平台对应扩展内的 `codex` 可执行文件、独立 `app-server` 参数及 `/proc/PID/stat` 启动时间。观察中身份或启动标识变化，整次结果未知。
- 用目标 PID 的 `/proc/PID/fd` socket inode 与 `/proc/PID/net/tcp` 求交，只接受 `ESTABLISHED` 且对端为 `127.0.0.1:<当前远端代理端口>` 的连接。其他进程的 socket、其他地址和端口均不能形成证据。
- 前置检查使用与生产 v3 一致的有效注册扩展及注册摘要，不把卸载残留目录当作活动版本。注册异常或候选不符时停止。
- 开始前建立连接基线，每次等待 250 ms 后采样，以实际时间截止并限制最多每秒四次的理论次数；进程信息读取有耗时，回执保存实际采样次数。仅窗口中新增连接可形成 `target-process-connection-observed`。启动标识和 inode 用十进制字符串保留，避免 JS 安全整数丢失精度。
- 采集前后及用户确认返回后复核记录来源；目标/入口变化则证据失效。采集持实例锁，与自动验收探针串行。
- 采样前已有的长连接、采样间隙内结束的短连接、权限不足、超过描述符预算或进程退出均不能报通过。收到新回复不会把未知连接升级为已观察。
- 该证据证明目标进程在窗口内建立到代理的连接，不读取内容，也不独立证明某个具体 HTTPS 目的地或请求内容。验收时结合对应目标、用户窗口内新回复和五层检查一起评估；不能用同时段代理日志替代进程关联。
- 远端只有 `/proc` 读取和有限等待，没有临时文件、安装、kill 或配置写入。Ctrl+C 取消通过现有 SSH 传输收尾；尚未以真实强关试验证明所有生命周期分支。
