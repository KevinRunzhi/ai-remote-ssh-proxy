## 1. 执行原则与完成定义

目标：Windows 用户解压工具包并双击，通过本地网页给出 SSH 和代理参数，在原生终端完成认证，经同一引导配置全新 Linux 容器中的 VS Code Remote SSH 与 Codex；旧容器销毁后可弃用并初始化新容器。

约束优先级为安全边界与已确认 PRD、对应架构、本文执行细节。发现无法同时满足时先记录具体冲突并修订对应文档，不隐式扩大范围。运行事实以脱敏证据为准，文档勾选不能代替实测。

- S00–S10 是同一版本的内部任务，不是需要用户逐版批准的产品版本。
- 从第 12 节第一个未完成任务执行；完成相关验证并登记证据后再标完成。可推进不依赖阻塞项的工作，但不能将依赖未验证的任务报为完成。
- 任务中的文件名是职责落点，可合并小文件；操作契约、安全不变量和完成判据不能省略。不建立插件框架、通用事务引擎或远端服务。
- 保留用户已有修改。单元与故障测试使用受控夹具；真实容器仅做正常准备、配置、检查和移除，不对真实用户环境注入断线或损坏。
- 后续 GitHub Issues 使用 Sxx 标识关联具体任务；本次编写 Spec 不创建远端 Issue、不提交代码，也不执行初始化。

最终交付需同时满足：S00–S10 全部完成、A01–A23 有对应通过证据、同一候选 ZIP 完成 A→弃用不可达 A→全新 B 的闭环。用户密码、官方登录、重连和真实请求可集中在验收时段完成；失败必须修复复验。

## 2. 术语、状态与不变量

| 名称 | 定义 |
| --- | --- |
| targetId | 本机随机 UUID，表示用户声明的一次容器生命周期；不是地址、alias 或真实性证明 |
| cycleId | 同一目标的一次代理配置周期；正常移除后，重新配置建立新周期 |
| operationId | 本次 initialize/resume/verify/remove/abandon 调用的随机 UUID |
| writeId | 本次 apply/restore/cleanup 动作的随机 UUID；同一 operationId 可包含多次不同写入 |
| requestId | 页面本次请求的去重标识，只在当前服务进程有效；不是远端操作身份 |
| resource | 连接块、反向转发或 settings 代理字段之一，具有独立状态和恢复依据 |
| previewRevision | 本次操作内一个具体预览/问题的版本；确认只能授权对应计划 |
| targetRevision / entryRevision | 目标记录与入口记录各自递增的 revision；二者不能直接比较相等 |
| firstRecovery | 当前资源配置周期首次确定的归属和逆操作，不被重跑或移除覆盖 |
| pendingWrite | 本次 apply/restore/cleanup 动作的意图；与 firstRecovery 分开保存 |

必须贯穿所有入口的不变量：

1. 密码只进入 OpenSSH 原生终端，官方登录只在官方界面；不读取 Codex 凭证、不发送模型请求。
2. 所有目标配置写入有精确预览、对应确认、锁后复核及预先持久化的写入意图。
3. 等价值可复用但不取得删除所有权；只恢复工具拥有且当前状态可证明的增量。
4. 正常移除保留 SSH 连接；连接清理只在弃用流程单独确认后处理工具新建的部分。
5. 阶段失败或取消保留此前成功阶段，只收尾当前未完成动作；软件不自动卸载。
6. 任何读配置、写配置和检查 SSH/SCP 连接都清除转发与连接复用；正式转发只由用户 VS Code 会话提供。
7. 原写入可能仍在执行时，不恢复或重试同一资源；不把本机 SSH 退出当作远端结束证据。
8. 同一数据目录仅一个工作实例，实例内仅一个业务操作；未知写入标记跨重启保留。
9. 新建/重建永远新 targetId，不把旧目标远端逆操作用于新目标；弃用不要求旧远端可达。
10. 主机密钥、TLS、访问权限和未知占用不能为了继续而绕过；不修改 known_hosts、sshd、全局环境或自动更新策略。
11. 配置已写入、自动检查通过、用户收到新回复、实际代理路径已归因是不同结论，页面分别显示。
12. 不记录原始 stderr、完整配置、完整进程环境、密码、Token、私钥或请求内容。页面仅接收白名单状态投影。

## 3. 支持样本与输入契约

### 3.1 样本冻结

S00 选择候选组合，各项能力经对应任务验证、S10 汇总验收后才能写成“支持”。不得将历史 E2E 的版本直接标为新流程已通过。

| 项目 | 必须登记的值 |
| --- | --- |
| 本机 | Windows 11 版本、x64、普通用户权限、默认终端与浏览器 |
| 工具运行时 | Node 精确受支持版本、架构、官方来源及校验值；满足项目最低版本 |
| VS Code | 实际安装位置、精确版本、Remote SSH 精确版本、实际 ssh.exe 与 config 入口 |
| Linux | 发行版/架构/基础库、用户与 home、shell/基础工具、监听检查方式、SCP/SFTP 能力 |
| Codex | 已验证扩展版本、平台包及后端版本、公开安装路径、代理启动行为核对方法 |
| 安装网络 | Remote SSH 准备 Server、用户商店安装及 Codex 目标 HTTPS 各端的可用网络路径 |

缺少本机软件给具体官方安装指引，不静默提权安装。缺少 Linux 工具、传输或转发权限时报告阻塞，不代改服务器。基础预检不得依赖已装 Server 或 Codex。

### 3.2 字段与解析

| 字段 | 约定 |
| --- | --- |
| inputMode | direct 或 alias；粘贴简单 ssh 命令先转换成其中一种 |
| hostname | 普通 ASCII 主机名或 IPv4，不含空白、控制字符、协议、路径或前导短横线；IPv4 须各段合法；IPv6/跳板不在本版 |
| username | 必填的普通 Linux 登录名，初版接受 `[A-Za-z0-9_][A-Za-z0-9_.-]{0,63}`；不从本机用户名猜测，不接受用户@主机的混合字段 |
| sshPort | 整数 1–65535，缺省 22；与代理端口分别校验 |
| alias | 沿用 `^[A-Za-z0-9][A-Za-z0-9._-]{0,254}$`；新目标默认生成未占用的 `codex-` 加 UUID 片段，冲突重新生成 |
| localProxy | 沿用无认证 `http://127.0.0.1:端口` 或 `http://localhost:端口`，只允许空路径或 `/`；无查询/片段；归一为 127.0.0.1 |
| remotePort | 整数 1024–65535，首次默认 17890，之后使用已确认偏好；不自动抢占或换端口 |
| 本地代理端口 | 沿用既有 1024–65535 范围；保存归一 URL，不另外保存相互矛盾的端口值 |
| sshConfig | 已确认的本机绝对路径；普通文件或明确的受限新建路径；拒绝链接/复杂布局，不用用户值拼 shell |
| remoteSettings | 标准环境由运行安装依据定位；非标准场景允许明确确认 Linux 绝对路径，仍需归属校验；拒绝控制字符和猜测目录 |

简单命令仅支持 `ssh [-p 端口] [-l 用户名] 用户@主机`、`ssh [-p 端口] -l 用户名 主机`、`ssh alias`。仅允许受控分词及配对引号，重复/矛盾字段拒绝；端口覆盖 alias 的复杂命令、`-o/-F/-i/-J/-R`、附加远端命令、管道、重定向、分号、反引号、变量展开等均拒绝并引导分字段输入。不得先执行再判断。已有密钥通过原 alias、默认 OpenSSH 或 agent 使用，工具不读取私钥。

用户选择已有 alias 时，实际用户/地址/端口由同一 ssh.exe/config 的有效配置取得并展示；不把 alias 名当作 hostname。直接连接预检的参数必须与待建立连接的语义一致，落地后再核对 `ssh -G`。

偏好仅保存代理、默认远端端口及已确认的本机工具/config 入口等非秘密本机默认值，不保存旧容器地址、远端路径或逆操作。更改偏好不修改当前目标；更换当前代理参数须先移除当前周期，再确认新周期。

## 4. 数据与持久化契约

以下是内部字段的最小语义，不是对外稳定协议。实现可增加非秘密证据字段，不可省略身份、存在性或恢复依据。未知 schema 拒绝修改，不作宽松猜测。

### 4.1 文件与标识

固定在 `%LOCALAPPDATA%/codex-remote-ssh-proxy-e2e/`，沿用当前用户 ACL。路径中的 targetId/cycleId/operationId 仅来自本机生成且校验过的 UUID，不能由页面当作文件路径传入。

```text
preferences.json
active.json
targets/<targetId>.json
instance.lock
operation.lock
```

| 文件 | 最小字段/约定 |
| --- | --- |
| preferences.json | version:1、revision、localProxy、remotePort、已确认工具入口；CAS 更新 |
| active.json | version:3、entryRevision、currentTargetId 或 null、lastTransitionId 或 null；无目标也保留 |
| targets/<id>.json | version:3、targetId、targetRevision、lifecycle、connection、connectionResource、currentCycleId、proxyCycles、preparation、lastChecks、pendingTransition |
| instance.lock | ownerId、PID、进程启动身份；当前版本网页/CLI 全存活期持有，无 HTTP Token |
| operation.lock | 保持原路径与独占创建语义；新写入可带 owner 信息，不能把旧 PID 格式误认成可删的坏文件 |

`lifecycle` 为 active/abandoning/archived。代理移除是周期状态，不等于目标已弃用。connection 包含 alias、实际 hostname/user/port、sshConfig 及可取得的非秘密身份线索；未知线索明确为 unknown，不编造已验证身份。

每个 proxyCycle 包含 cycleId、状态 preparing/configured/removed、forwarding 和 settings 两个 Resource、开始及结束结果。connectionResource 跨周期保留。先确认新周期，再切换 currentCycleId；旧周期只保存最小恢复信息与结果，不提供历史写入按钮。

### 4.2 Resource 与写入意图

```js
// 语义示意；实现仍为 JavaScript 普通对象，不引入类型框架。
Resource = {
  state: 'untouched', // untouched/intended/applied/reused/reverted/unknown
  path: null,        // settings 尚未定位时允许 null
  firstRecovery: null,
  pendingWrite: null,
  lastOutcome: null
};
// firstRecovery：owned、原存在性、原/应用后摘要、最小插入片段或字段逆操作。
// pendingWrite：operationId、writeId、action(apply/restore/cleanup)、confirmedPreviewRevision、
//   targetRevisionAtPlan、beforeState、expectedBefore、expectedAfter、stageRef、结果。
// expectedBefore/After：{ exists: boolean, sha256: string|null }，不存在不等于空文件。
```

摘要针对原始 UTF-8 文件字节，保留 BOM、注释和换行；不能先格式化再计算。解析失败、重复键、过大或非支持编码均停止。首次恢复依据不可被重跑/移除覆盖；pendingWrite 描述本次动作，完成后保留必要结果即可，不保存完整执行日志或完整配置。

初始容量边界：业务 JSON 请求体 64 KiB、单配置文件 1 MiB、待解析单次 stdout 2 MiB；超限终止对应读取并返回脱敏错误，不输出截断正文。数值可在受控样本中调整并记录，不以无限缓存代替处理。

### 4.3 两种锁与更新顺序

1. 启动网页或新版 CLI，独占取得 instance.lock，失败仅提示已有实例，不抢占；包括等待安装、认证、用户确认和收尾。
2. 进入真正写入前取原 operation.lock，复读目标与入口及相关文件；锁顺序始终为实例锁→写入锁。
3. 预览/人工步骤的业务等待不长持 operation.lock；发起写入后至结果落盘或恢复收尾，不能开始另一写入阶段。
4. 元数据更新、偏好更新、迁移、归档与配置更新都遵守写入锁。释放时核对归属，不能删除其他实例的锁。
5. PID 不存在、PID 被复用或时间已久，均不直接授权删锁。遗留锁经进程启动身份、已知子进程及记录核对并由用户确认后，采用独占恢复入口处理；有歧义只读提示。用户不需手改 JSON。
   实现采用 Windows 系统 Mutex 保护恢复入口，崩溃后由系统释放；正常实例同时检查恢复标记。新锁保存系统报告的真实进程启动时间。当前保守地要求旧实例/恢复入口 PID 均不存在，并经系统进程普查确认没有任何 SSH/SCP（涵盖可能遗留的传输及其 SSH 子进程）；活跃或复用 PID 均拒绝接管，不结束未知进程。确认前后复核入口/目标/锁摘要和进程普查，原生终端 `RECOVER` 确认后只移除已核对锁、保留摘要回执并取得新实例锁。其他 SSH 会话也会阻止接管，属于当前实现限制；不以超时或两次稳定文件摘要替代这些条件。
6. 首次无旧记录时，持原锁建立 version:3 入口，再允许任何目标配置写入。遇 v1/v2 先确认迁移；旧 CLI 只承诺在同一目录遇 v3 安全拒绝。

元数据单文件更新：核对旧文件类型/摘要或不存在条件→同目录独占临时文件→限制 ACL/保持权限→写入并同步→替换→复读。失败不继续目标写入。不存在时的创建必须防止覆盖刚出现的未知文件，不能复用“已有文件必定存在”的旧函数路径。

### 4.4 入口切换与旧记录迁移

新建、归档、重新配置周期及迁移均保留可核对意图。目标记录先保存 transitionId、种类、已确认计划 revision、预期旧入口摘要/entryRevision、from/to targetId、必要来源摘要，再原子切换入口并登记 lastTransitionId，最后补记完成。周期切换保存在同一个目标文件中，无需切换 active.json。

旧 v1/v2 转换仅搬运原必要恢复信息、phase、暂存定位及归属，不把已配置状态当作“修改前状态”，不把旧转发标记升级成连接块所有权。持锁时再次校验来源摘要；转换成功复读后才切换入口。v3 入口替换旧 active.json 前，新记录必须已保存全部必要恢复依据。

当前兼容边界：旧远端 unknown 没有 v3 可关闭许可时，不能仅凭 phase=applied 或相同摘要开始远端写入；继续/移除返回明确的旧远端待核对结果，提供不连接远端的弃用入口。若本机核对确认原写入已经结束，但真实文件有冲突，可在单独预览中明确“全部保留后弃用”；记录保留、文件不变。此边界不宣称旧远端已恢复，完整旧版自动移除仍待原任务结束证明。

启动只读核对规则：

| 观察结果 | 动作 |
| --- | --- |
| 入口与完整当前目标一致 | 展示历史进度，等待明确操作；不自动连接/写目标 |
| 唯一已确认的未完成切换，预期旧入口仍精确匹配 | 锁后复核，可只补记/切换元数据并展示说明 |
| 入口已切换，目标完成标志缺失 | transitionId 唯一吻合才补记；不重放配置 |
| 多孤立候选、来源变化、损坏或未知 schema | 冻结受影响操作，显示只读核对、保留并弃用等合法选择；保留全部恢复依据 |
| 有未完成配置意图 | 元数据核对不能清除资源 unknown；进入第 5 节的原操作结束及摘要核对 |

已归档且完成的记录不算待激活候选；不能按文件时间选择“最新”重放。无法解释的损坏不承诺自动修复，给受控恢复说明而非要求用户删除 active.json。

## 5. 配置事务与恢复算法

### 5.1 纯计划与预览

`config.mjs` 产出纯计划：资源、路径、精确允许增量、影响范围、预期前后状态、归属与逆操作；纯计划函数不得访问网络或写文件。

- SSH：只支持普通文件中的唯一单 alias 字面 Host 块，拒绝 Include/Match/重复目标/链接及不完整标记。新块插入保留原全局前导语义，不能把原全局设置意外纳入新 Host。
- 新连接的 HostName/User/Port 与转发分开计划。新建块有连接归属标记，转发有独立标记；标记包含 targetId，转发再区分 cycleId。兼容旧标记，但不接管未知或用户等价片段。
- 连接子步骤确认完成后，转发 beforeHash 以“已包含连接块”的文本为准；恢复转发不会删除连接。
- settings：仅 `http.useLocalProxyConfiguration=false`、`http.proxy=http://127.0.0.1:<remotePort>`，JSONC 局部编辑，保持无关内容。原有不同值作为冲突停止。
- 预览只展示工具增量/目标字段变化与必要路径，不展示整份文件；相关原值含秘密时拒绝修改，不将秘密带入预览或记录。

### 5.2 应用步骤

每个 apply/restore/cleanup 动作依次执行：生成计划→展示并确认→取写入锁→核对目标/revision/文件→计划变化则释放并重新预览→持久化 pendingWrite→实际受限写入→复读→更新资源事实→清理已结束的本次暂存。

本机连接与转发可在同一次预览后依次执行，但具有两份独立动作意图。连接验证除文本外还核对 `ssh -G` 的实际目标字段；转发子步骤只允许获准的转发有效差异。若连接失败恢复本次连接动作；连接已成功而转发失败则保留连接，仅收尾转发动作。

远端沿用受限本地暂存→SCP→同目录临时文件→权限保持→摘要复核→替换→复读。改动前后校验原文件类型、父目录依据及允许路径；只创建已证明归属的缺失 settings 文件，不创建猜测 Server 目录。临时目录 0700、文件 0600，现有用户文件保持原权限。

这是有限的替换与冲突保护，不是跨机原子事务，也不是针对外部编辑器的操作系统 CAS。实际写入期间避免手动编辑相关文件；可观察的摘要变化立即停止，不能宣称能防止任意并发外部写入。

### 5.3 结果未知及恢复

先按第 8 节关闭原写入许可并确认没有仍能提交的原写入，再读取当前资源。若无法做到，保持 unknown，阻止同资源修改。

| 当前真实状态 | 收敛结果 |
| --- | --- |
| 等于本次 pendingWrite.expectedAfter | 本次动作已发生；按 action 记录 applied/reverted/已清理，不重复写 |
| 等于 expectedBefore | 本次动作未发生；保留 beforeState，不用本次失败覆盖此前成功阶段 |
| 两者均不等或无法读取 | 保留意图及恢复依据，标为 unknown/冲突，不覆盖 |

若失败需要撤销本次已确认的未完成动作，另存 restore 意图后执行受限逆操作；使用独立恢复 signal。恢复动作也可能丢失结果，仍按本表核对，不递归无限恢复。

正常 remove 先处理工具拥有的远端字段，再处理工具拥有的本机转发，始终保留连接。settings 从未触及且无远端暂存时不访问远端；未取得所有权的等价值不删除。文件原本不存在时，仅在当前确为工具内容且摘要吻合才删除；已有空文件不能误删。已恢复的资源跳过，不要求再次等于原应用后摘要。

若配置未修改但产生了已知远端暂存，代理字段仍不应被当作已触及；暂存残留独立报告。可移除本机增量，但在暂存尚未清理时不得报告“全部清理完成”。

## 6. 五种操作的可见行为

### 6.1 initialize：明确的新建/重建

输入须声明 new-or-rebuilt。当前有目标时先通过单独 abandon 操作归档，不能让 initialize 隐式弃用或覆盖；新建 targetId 后不继承旧连接地址、远端路径、摘要或逆操作。

1. 显示解析结果与目标声明；本机工具、实际 SSH 入口和本地代理检查通过。
2. 无 alias 时用明确参数数组只读探测目标 Linux；有 alias 时先核对有效连接语义。基础预检包含用户/home、必要工具、目标端口和传输能力，不要求 Codex。
3. 预览并应用连接与转发两个子步骤。首次新增转发要求候选端口空闲；已有等价映射走既有复用检查，不把未知监听当作自己的转发。
4. 通过公开入口打开 VS Code 连接，必要点击由用户执行；等待后探测真实 Server 安装/运行及 user data 归属，不能信任启动进程的退出码。
5. 定位实际 Machine settings，父目录依据成立后才允许创建缺失文件；预览、确认并应用两个代理字段。
6. 本次实际修改 settings 或转发时，提示保存工作、关闭对应远端窗口并重连。settings 等价复用且本次未改转发时不增加该等待；预览明确展示复用字段及无删除所有权。继续独立核对生效结果，未通过仍提示重连；按已验证的官方入口安装或复用兼容 Codex。
7. 必要时再次重连，用户完成官方登录；重新定位目标 app-server，执行独立五层检查。
8. 提示用户发起真实请求、确认新回复。代理归因单独登记；没有实际归因证据，结果只可为“用户确认可用，代理路径未确认”。

安装/登录/网络失败保留此前成功阶段。若等待中退出，进度记录可再次检查后继续；不将“用户点击已完成”直接当作 Server/Codex 已装或进程已重启的证据。

### 6.2 resume：继续原容器

输入 targetId、expectedTargetRevision 及 original-container 声明。当前目标必须匹配且未归档；abandoning 只允许继续核对/弃用，不恢复初始化。

- 首先处理未完成写入与元数据切换；再核对原用户、路径、实际配置及可得身份线索。主机密钥检查留给 OpenSSH；缺失的可选线索如实标 unknown，不冒充强身份。
- 有不一致停止，保留原基线并提供声明新建/重建的入口；不能自动修正旧记录适配“新目标”。
- 已完成阶段重新验证前提后跳过写入；历史网络检查、进程 PID 和人工可用确认不作为本次实时通过依据。
- 当前周期已 removed 时，不直接重放。用户明确选择重新配置并确认新的代理计划后，创建新 cycleId，保留连接和旧周期结果。

### 6.3 verify：独立检查

只检查当前声明的原容器，不能创建转发、改代理配置或自动请求模型。只读检查不需要配置写入预览，但要满足单实例和未解决写入的限制。

| 层 | 判据 |
| --- | --- |
| local-proxy | 经用户指定本机 HTTP 代理探测固定目标 HTTPS，代理/TLS/目标响应分别分类 |
| ssh | 同一实际 ssh.exe/config 能完成固定只读命令；认证提示不被工具读取 |
| remote-endpoint | 实际回环入口及有效映射成立，无公网/wildcard 监听；无监听提示重连，未知占用停止 |
| target-https | 远端显式经该入口请求目标 HTTPS，TLS 成立；无凭证目标 401 可表示网络可达，代理 407/自身错误不通过 |
| codex-process | 指定用户、可执行文件与独立 app-server 参数及代理环境匹配；多候选须选择并核对，PID 单独不足以证明身份 |

沿用既有 curl 禁用用户默认配置、显式 proxy/noproxy、TLS 校验与超时策略。自动探测结束后才发起人工请求归因，避免把探测流量当成 Codex 请求。进程归因可用有限只读维护者工具，不要求开发完整观察界面。

维护者实现见 [只读采集说明](PROXY_OBSERVATION_V0.3.md)：退出网页后独占实例，前置检查完成后有限采样，核对 UID/候选包路径/app-server 参数/进程启动标识，将 PID 持有的 socket inode 与指定 IPv4 回环代理 ESTABLISHED 连接求交；仅窗口中新增连接形成连接证据。基线已有连接、采样遗漏、权限不足或身份变化均保留未知。此实现不写配置或业务记录、不随包交付；真实 Linux 和用户请求证据尚待取得。

结果包含各层 pass/fail/unknown、检查时间和下一步，不返回完整进程环境或输出。“自动检查通过”不等于真实请求与路径均已确认。

### 6.4 remove：移除代理并保留连接

1. 绑定当前目标与当前周期；核对未完成动作后，预览实际拥有的远端字段、本机转发及保留的连接。
2. settings untouched 且没有对应写入意图时，直接按本机记录处理转发；无须知道 settings 路径或登录远端。
3. 曾拥有远端字段时，核对身份与摘要后恢复该字段，再撤销本机转发。无权删除的等价值明确显示“保留”，不伪报已恢复为原值。
4. 任一步骤结果未知时保留记录，显示已完成和未确认部分；下次只处理剩余动作。
5. 可确认的代理恢复完成后将当前周期记 removed，保留 connectionResource、必要周期恢复信息和 v3 入口；提示重连以释放原 VS Code 会话仍持有的转发。

文件里的转发被删除，不代表当前 VS Code 的 SSH 会话已释放监听；工具不自动关闭该会话。重复 remove 无新修改。远端不可达但曾修改远端时，提供 abandon 入口，不将普通 remove 假装完整成功。

### 6.5 abandon：弃用旧目标

1. 绑定当前目标，确认本机旧操作/子进程结束且配置稳定；未知本机动作先核对。明确提示旧远端清理可能未知。
   本机核对器仅在独占实例下完成实际读取、确认本机原写入已经结束后，保存 `lastOutcome.localWriterClosed`；该字段不适用于远端。存在冲突且该证明完整时，可经“全部保留后弃用”确认直接进入 abandoning/localCleanup=retained。缺证明、未匹配原 writeId 或只凭未知标记仍禁止弃用，不借归档绕过在途写入。
2. 用户确认后持久化 abandoning 与弃用计划；不连接旧远端。
3. 可选本机清理先预览工具转发，再单独预览是否清理工具新建连接；按顺序更新资源事实。原有连接与用户等价值保留，摘要冲突可选择全部保留。
4. 清理已结束或用户选择保留后，记录旧远端/暂存未确认状态，按切换协议归档并将 currentTargetId 置 null。
5. 用户可初始化 B。B 使用新 targetId 和默认新 alias，当前文件作为新基线；不重试 A 的远端动作，也不在 B 的同名路径检查 A 的状态。

归档后仅提供残留说明，不提供按旧整文件摘要历史清理的按钮。归档中断后从 abandoning 继续核对，不自动恢复 A 的初始化。复用旧 alias 须先安全解决旧块冲突；无法解决则保留并使用新 alias。

## 7. 工作流、HTTP 与单页契约

### 7.1 共享工作流

内部入口沿用架构的 `runOperation(input, io, dependencies)`，CLI 与网页各是一个 adapter。普通函数即可；配置计划/恢复判断隐藏在共享模块内，adapter 不推测或重写状态机。

唯一切换/旧记录的元数据核对使用同一入口：`{ kind: 'resume', stateRecovery: { expectedEntryHash } }`，摘要可为缺失入口的 `null`。该形式与目标/连接参数互斥；显式预览确认并复核全部候选来源后，只执行迁移或已确认唯一切换的元数据收敛，不 SSH、不重放配置。GET 不触发核对，完成后重新声明目标再开始业务操作。

```js
// input：kind、明确的目标声明/targetId、expectedTargetRevision、已校验参数。
// io：notify(event)、confirm(preview)、waitForUser(action)。
// dependencies：实际进程/文件/时钟/标识产生器等必要替换点。
// 返回：{ outcome, stage, checks, nextAction, userUsability, proxyAttribution }。
```

运行状态为 idle/running/waiting-user/cancelling/succeeded/cancelled/failed/recovery-required。succeeded 只表示当前操作职责完成；初始化若停在人工准备步骤，应返回明确 nextAction 与未完成业务结果，不显示“Codex 已可用”。阶段与业务结果不靠中文字符串反向解析。

结果快照至少包含 operationId、kind、stateRevision、status、stage、必要目标摘要、逐层 checks、waitingQuestion、nextAction、检查时间。历史完成结果可持久保存非秘密摘要，重启后标为历史；本次问题与 requestId 去重缓存不跨进程恢复，继续时重新生成问题。

### 7.2 本地 HTTP

| 接口 | 输入 | 行为与响应 |
| --- | --- | --- |
| GET /api/state | 会话头 | 200，仅读内存白名单快照，不发 SSH、不写状态；刷新页面不恢复执行 |
| POST /api/preferences | requestId、expectedPreferencesRevision、明确偏好 | 校验且持锁保存；活动业务操作期间返回 busy，不改变当前目标参数 |
| POST /api/operations | requestId、kind、目标声明或 targetId/revision、参数 | 校验后返回 202 与 operationId，耗时操作异步执行 |
| POST /api/operations/:id/answer | requestId、questionId、previewRevision、枚举 choice | 只接受本次有效问题；200 确认接收不等于任务完成 |
| POST /api/operations/:id/cancel | requestId | 202 或已有终态；先 cancelling 再收尾，不立刻宣称已取消 |
| POST /api/shutdown | requestId | 202，先取消/收尾及落盘再关监听；页面可轮询到可取得的最终结果 |

HTTP 400 为输入/结构错误，403 为 Host/Origin/会话校验失败，404 为未知固定资源或操作，409 为 busy/revision 冲突/过期回答，413 为请求过大；无法安全处理的内部错误仅给错误码与脱敏说明。HTTP 202、200 或启动进程退出码均不能代替业务结果。

当前进程以 requestId 绑定规范化请求摘要去重：相同 id/相同内容返回原操作或原接收结果，相同 id/不同内容拒绝。新 requestId 但业务仍忙也不能新开操作。重复 answer 不重复推进；取消与退出也必须幂等。预览过期、文件摘要变化或 targetRevision 变化需要新预览，旧确认不能授权新内容。

服务只绑定 `127.0.0.1:0`，校验实际 Host；随机至少 256 bit 会话令牌经 URL fragment 交付，进入页面内存/sessionStorage 后移除地址栏片段。所有 API 校验令牌头，写请求另校验同源 Origin、JSON、大小；关闭 CORS，拒绝跨站预检。固定静态资源白名单，禁止任意文件/命令入口。

初始 CSP 限制脚本/样式/连接为随包同源资源，禁止嵌入和外部脚本，不使用内联事件或 CDN；no-store、no-referrer。令牌不写日志、不进入持久状态；会话失效时提示重启后使用新地址，不自动寻找或复用旧 Token。

### 7.3 单页交互

| 区域 | 必须展示/可操作内容 |
| --- | --- |
| 本机准备 | 缺失软件、实际 VS Code/SSH/config 入口与安装/定位指引 |
| 连接及代理表单 | 新建/重建与继续的区别、字段解析结果、已确认偏好预填、字段错误 |
| 当前目标 | alias、必要地址/用户、历史或本次状态标识；不展示逆操作或完整配置 |
| 步骤列表 | 当前 stage、结果、下一步；无未经测量的百分比 |
| 预览/人工步骤 | 精确允许增量与影响、确认/取消；认证提示切回原生终端 |
| 结果与恢复 | 五层检查、新回复确认与路径归因分别展示；未知状态、残留及合法恢复选择 |
| 操作区 | initialize/resume/verify/remove/abandon、取消、退出；busy 时禁用冲突操作 |

约一秒轮询状态；重载只 GET，不用 mounted/load 事件重发 POST。使用文本节点渲染用户内容及错误；不复制 SSH 终端输出，不提供密码/Token 输入。关闭标签页不等于取消，原终端继续承担进程；第二次双击不创建另一个页面流程。

主机密钥异常时提供可信指纹核实及官方处理指引，由用户完成后重试；不捕获原始 stderr 来猜测“认证成功”，不自动改 known_hosts。该异常的必要人工操作单独记录，不掩盖标准路径的零手工配置要求。

## 8. 传输、远端写入许可与取消

### 8.1 进程接口

保留系统 OpenSSH，`shell:false`、参数数组、stdin/stderr 继承真实终端，stdout 管道只供解析。父进程不占用 stdin，不创建 readline 密码问题；网页确认由 Promise 等待。runSsh/runScp 及嵌套调用都显式传递本次 signal/notify，不假定顶层依赖注入会自动覆盖内部函数。

基础环境检查与扩展行为检查分离。每次 SSH/SCP 使用同一工具和 config，带 ClearAllForwardings=yes、ControlMaster=no、ControlPath=none，不增加测试转发。远端固定脚本仍需严格参数校验/编码；Base64 不是加密，完整配置不进命令参数。

初始时限：SSH 认证 120 秒，收到固定就绪标记后操作 60 秒；SCP 总时限初值 120 秒。预览确认 10 分钟失效；安装/重连等待不伪装成 HTTP 超时，用户可取消并保留进度。恢复另有总预算初值 300 秒，每次认证/命令仍受分段限制，超时保留记录而非无限重试。样本确需调整时记录原因，不承诺一次密码。

### 8.2 远端写入许可协议

为解决“SSH 已退出但旧写入可能稍后提交”，远端写入和恢复使用同一套有限许可。该协议只占用本次私有暂存，不是容器身份文件或远端服务；S05 必须用受控延迟验证，未通过不得接真实配置。

1. 为每次远端动作生成 writeId，并关联本次 operationId；在已验证可写的远端父目录选择本次唯一私有 stage 路径，**分配前先持久化定位信息**。stage 独占创建为 0700，拒绝链接/归属不符，不复用其他动作目录。
2. stage 中保存最小请求身份、许可状态 open/closed 和必要结果；配置载荷仍为受限临时文件。创建 stage 与启动写入分开，只有 stage 信息落盘并复核后才允许执行写入器。
3. 写入器不创建缺失的 stage；先用原子 mkdir 独占取得 stage 内 write.guard，再复核 operationId/writeId、目录归属及许可 open，最后检查当前摘要并替换。没有许可或 stage 不存在必须停止。
4. 所有可能提交目标文件的动作都在 guard 内同步执行，不遗留后台写入子进程。正常结束先落盘最小结果、关闭许可、确认本次提交/子步骤结束，最后释放 guard 并返回完整回执。
5. 不能在 EXIT/HUP/取消陷阱中无条件移除 guard；异常退出不能成为“已无写入”的证据。未知或残留 guard 保守阻止下一次写入，不因超时/PID 不存在自动偷锁。
6. 取消/结果丢失后的核对器尝试取得同一 guard；取得后先关闭原许可，再核对结果及真实摘要。原写入若尚未开始，之后只能看到 closed 或缺失 stage 而停止；若仍在临界区，核对器取不到 guard，必须保留 unknown。
7. 只有原许可已关闭、无原提交仍可进行时，才允许另存 restore 意图并开始恢复。固定等待、相同摘要、单独 PID 或本机 SSH 退出都不能代替本协议。guard 无法安全取得时只读说明，保留恢复依据，不自动结束未知远端进程。
8. 删除 stage 前先确认原许可关闭、原任务不再使用该目录；删除后旧写入器也不能重建目录继续。无法清理时报告本次私有残留，不将完整载荷用作长期备份。

guard 不是供外部程序遵守的文件锁，不替代当前摘要复核；也不能证明容器身份。进程启动身份/最小完成记录可辅助解释异常，不作为忽略 guard 的捷径。若当前样本无法满足上述独占与有界执行，S05 标阻塞并修订实现，不削弱恢复条件。

### 8.3 取消顺序

取消→禁用新阶段与问题回答→取消正常 signal 并结束本次已知子进程→确认原写入许可/本机动作→新恢复控制器处理当前未完成步骤→保存准确结果→允许退出。不能复用已 aborted 的 signal。

重复取消只结束收尾并记录 recovery-required，不重新启动恢复。未知标记跨重启保留；原写入未确认前不删掉它仍在使用的暂存。正常退出先收尾、落盘、关监听，再释放本次拥有的锁；强关终端靠预存意图恢复，不依赖退出事件一定执行。工具不结束用户 VS Code 会话、代理或 Codex 进程。

## 10. 打包与 CLI 兼容

ZIP 至少包含 start.cmd、runtime/node.exe、app 静态资源、应用脚本、生产依赖 jsonc-parser 及许可证/版本说明；用户数据必须在包外。发布脚本验证受支持运行时的精确来源、架构与校验，不从开发机 PATH 随意复制。

- start.cmd 用自身目录的固定路径定位随包 Node 与入口，不拼接用户参数，不依赖 cwd/PATH 中的 Node，不用 PowerShell Bypass。
- 原生终端可见且 TTY 可用，HTTP 等待不阻塞认证；浏览器失败时提供本次 fragment 地址。包含中文、空格和特殊字符的目录必须实装验证，不能仅认为加引号就已经支持。
- 开发/打包可用 npm ci 和开发机 Node，交付用户不需要源码、npm 或额外 Node。包内缺资源/运行时不匹配时先报错，不写用户配置。
- CLI 保留 configure/verify/remove 与已有合法参数，适配共享 v3 工作流及锁；配置首次进入或继续时明确生命周期，不静默推断。正常用户流程走网页，不为首版新增一套完整 CLI 管理产品。
- v1/v2 迁移覆盖已核对的原字段和暂存；旧二进制遇 version:3 拒绝，不要求它支持新数据。对同一旧记录的重复迁移不得生成多个活动目标。
- 移除保留连接属于 v0.3 明确变更；旧恢复测试应保留有价值的保护断言，更新已明确改变的存储/事务语义，不能靠删除故障测试让迁移通过。

新增运行依赖默认无；继续 JavaScript ESM、Node 内置 HTTP/测试、系统 ssh/scp/curl 与 jsonc-parser。确有必要新增依赖，先说明问题与现有能力限制并更新架构，不预建 TypeScript/打包前端框架或安装器。

### 11.2 必须注入的中断边界

所有夹具须能检查“没有误写目标/没有丢失恢复依据”，不只断言抛出错误。

1. 保存意图之前失败：配置未写；保存意图之后、真实写入之前失败：下次可证明本次未发生。
2. 写入完成、回执丢失：先关闭原提交许可，读到 expectedAfter 后只补记，不再次写入。
3. 真实文件为第三种状态：不覆盖、不移除用户内容，保留 unknown/冲突。
4. 连接完成转发失败、转发完成 Server 失败、settings 从未定位且远端离线：保留成功阶段，可只撤销本机代理。
5. remove 的远端字段已恢复、本机转发尚未恢复时中断：再次 remove 跳过已恢复资源，不误报新冲突。
6. apply/restore/cleanup 的任何远端动作：延迟进入 guard、临界区内取消、提交后失联、结果落盘前退出；始终最多一个可提交者。
7. 元数据每次替换边界、迁移来源变化、多个孤立候选、完整归档历史：不会错误激活旧目标，不按文件时间选记录。
8. 第二实例、新 CLI、重复 POST、过期回答、偏好并发、遗留锁、PID 复用：不会绕过原工作流推进或删除他人锁。
9. A 与 B 的地址/密钥/路径/文件内容相同：新建声明仍生成新身份，不调用 A 的远端读写/逆操作。
10. 已移除目标创建新周期：旧 firstRecovery 不覆盖新周期基线，新周期也不覆盖旧结果。
11. 配置/进程输出含测试秘密、原始错误含 Token、超大输入/输出：正文不进入页面、日志或持久记录。
12. 自动更新或安装得到另一版本、错误平台包、来源异常、本机 curl 可用但 VS Code 无法下载：不虚报安装/兼容成功。
