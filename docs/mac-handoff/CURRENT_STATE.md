## 必须保留的未知

- 干净 A 与全新 B 的首次 Server/商店安装全过程尚未完成集中验收。
- 当前样本的等价 settings 复用不能证明“缺失文件创建”或“工具实际拥有的远端设置恢复”。
- 远端许可与 SCP/SFTP 有真实 Linux 专用合成文件试验，但不是所有正式配置故障分支均已实测。
- 页面取消真实 SSH 有证据；ConPTY 写入控制字符不能证明物理 Ctrl+C。完整受控强关、SCP 传输中断、普通用户权限、Explorer 双击仍有待验证项。
- 自然中断后的 RECOVER 实测不能冒充受控强关矩阵。当前恢复策略会因系统其他 SSH/SCP 会话而保守阻塞。
- 旧远端 unknown 缺原任务结束证明时，不能按旧 phase 自动恢复；只能保持保护并说明可保留弃用的边界。
- UI renderer 超时通过正常重载恢复，后续重连正常；最初超时的唯一底层原因没有被证明。
- socket 证据不读取请求正文，不能独立识别具体请求或目标 HTTPS 站点。
- macOS 的安装路径、原生终端、权限、锁、启动签名与真实容器组合均未在本项目中验证。

## 原文档里的时间层次

原 PRD 开头“尚未实现”、旧架构表格“当前 CLI”等是创建时的设计背景；某些历史段落可能与后续实现状态不同。需求语义以当前 v0.3 条款为准，实现事实以源码和验证记录最新日期段为准。遇到矛盾应记录并核对，不把一句历史声明扩大成当前结论。

[原验证记录](../E2E_RUN_V0.3.md)保留了历史过程，包括曾失败和后来通过的结果。其 `artifacts/`、`.cache/` 路径仅用于原 Windows 工作区定位，原始产物未提交到 GitHub；Mac 端不能把这些引用当作仓库内证据文件。这里提供的是脱敏总结及对应源码，Mac 仍须生成自己的原始验收回执。

## Mac 不能继承的东西

不能继承 Windows 的数据目录、活动目标、instance/operation 锁、远端 stageRef、主机密钥信任或认证授权。新 Mac 使用独立本机状态；只有非秘密的参数偏好可以经明确选择后重新输入。这组文档没有可供继续的真实容器地址或恢复记录。

Mac 的最低 OS、首个架构、Node 版本、VS Code/Codex 组合、状态位置、双击形式、恢复锁方案都是待本机调查后确定的决策，不因为 Windows 使用过某版本就直接冻结为 Mac 基线。
