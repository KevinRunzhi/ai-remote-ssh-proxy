# Mac 迁移交接：先从这里阅读

整理日期：2026-10-24，Asia/Shanghai。对象：在 Mac 上接手开发的用户与 Codex。

这组文档用于理解既有 Windows 实现，再在实际 Mac 上分析并开发同一业务流程。它不是可直接在 macOS 运行的安装包，也不是已经冻结或验收的 Mac 版需求。此次只整理交接资料，没有在 Windows 上假装完成 Mac 适配。

## 阅读顺序

1. [总体思路](OVERVIEW.md)：目标、网络路径、架构、状态与安全原则。
2. [当前成果和证据边界](CURRENT_STATE.md)：哪些真实跑通过，哪些仅有测试，哪些没有完成。
3. [问题与解决经验](LESSONS_LEARNED.md)：实际踩坑、解决思路、不能照搬的结论。
4. [Mac 本机分析与实施建议](MAC_ANALYSIS_AND_PLAN.md)：逐模块改动表、先调查什么、实施与验收顺序。
5. [原项目文档导航](DOCUMENT_MAP.md)：PRD、架构、Spec、安全边界及历史文档的优先级。
6. [给 Mac Codex 的开场消息](CODEX_START_PROMPT.md)：可直接复制到新会话。
7. [官方资料与依据](SOURCES.md)：已查阅的官方入口及其能证明、不能证明的内容。

资料很多时，先读 1–4，再按文档导航补齐 v0.3 PRD、架构和 Spec 的相关章节。不要只读根目录旧 README 后直接开始执行历史 CLI。

## 在 Mac 上如何接手

按用户最终要求，交付方式为 GitHub 仓库，不另提供本地压缩包。在 Mac 上克隆仓库或更新到最新 `main`，先从 `docs/mac-handoff/README.md` 开始阅读。

- `docs/mac-handoff/`：本组交接文档。
- `docs/`：v0.3 需求、架构、Spec、验证记录与历史讨论。
- `app/`、`scripts/`、`tests/`：当前源码和测试，直接在仓库内核对。
- 根目录 `PRD.md`、`SECURITY.md`、`SPEC.md`、`TECHNICAL_ARCHITECTURE.md`：版本导航、安全约束及历史依据。
- Git 提交记录：实现与文档的可追溯版本；已推送的 Windows 实现基准为 `9118924`，交接文档随后单独提交。

本次提交不加入用户 SSH 配置、私钥、密码、登录文件、真实恢复记录、浏览器会话、原始远端输出、截图、开发缓存、运行时二进制和 `node_modules`。原根目录 README 下方仍保留 v0.1 使用说明，包括历史锁处理建议；不要将其用于 v0.3 锁恢复。仓库 `AGENTS.md` 的 Windows 首版范围是原项目约定；Mac 开发需结合新的用户目标，先明确需求增量与平台约定。

源码中的 Windows 平台限制、`.exe` 路径和历史文档都保留为参考事实，不代表 Mac 应沿用相同限制。请在新的 Mac 开发目录建立自己的需求与平台约定，不覆盖原项目作为“已移植”。

## 本次明确的方向

Mac 仍是本地控制端，远端仍是受信任的 Linux 容器；目标仍是 VS Code Remote SSH 里运行的 Codex。保持“本地网页 + 原生 SSH 认证终端 + 共享工作流”的方案，先分析最小平台适配，不重新做 VS Code 插件、Electron 应用、扩展下载器或云服务。

Windows 最新已记录自动测试为 165 项：160 通过、5 项可选 Linux 试验跳过、0 失败。该数字是历史 Windows 证据，不是交接时重新执行的结果，更不是 Mac 测试结果。Mac 端必须单独登记基线与跳过原因。

这些交接文档不携带旧容器接入信息。Mac 开发需要届时重新选择可信测试目标；Windows 记录中的“继续原目标”仅适用于原 Windows 用户状态，不能据此在 Mac 继续某个旧写入任务。
